# OPT10-T01: the gate's backward folded into `linear_2`'s input-gradient GEMM (29 October 2026)

Plan: `plans/opt-10.md`. Probe: `tools/bench/opt10_gate_epilogue.py` (source `ae6f5e45`). Records:
`results/opt10-T01-gate-epilogue-20261029/`.

**Verdict: the stop rule is met on the RTX 4000 Ada** for NbCl5 and NaNbO3. The fused kernel is 0.86 (NbCl5) and
0.79 (NaNbO3) of today's chain, saving 0.31 and 0.27 ms per gated interaction. MH-1 has two, so about 0.6 ms
(NbCl5, 3.0 % of its 20.7 ms step) and 0.53 ms (NaNbO3, 3.1 % of 17.0 ms), if the subgraph gain carries over to
the step. On NaCl it is 1.21× slower: there `segment_gemm`'s shape rule keeps the products on cuBLAS, and the
fused kernel would follow the same rule.

## What changes

In MH-1's gated chain (`GatedRows` with `segment_gemm`), the backward of `linear_2` writes, per gated segment
(D = 2l + 1 rows per atom), `drows = grad_l @ W_l^T` (`joined_products_input_grads`). A compiled elementwise
kernel then reads `drows`, the gated rows and the gates and writes `dgated = drows * gate` and
`dgate = sum_m drows * gated`.

The fused kernel tiles atoms, not rows. Per (atom block, column block) it runs one K-loop per component m, loads
the gate tile once, stores `acc * gate` and adds `acc * gated_m` into `dgate` in registers. So `drows` is never
written or read back, there are no atomics, and the m-sum needs no partial tensor. (A plain epilogue on today's
64-row tiles would have to write per-row partials as large as `u`, because 64 rows do not align with 3, 5 or 7
components per atom; that version saves almost nothing.)

## Setup

- murphy, RTX 4000 Ada (sm_89), `mace_cueq_oeq` (torch 2.14.1+cu130); idle check passed (23:47 UTC).
- Synthetic operands: 512 channels per segment, segments 0e, 1o, 2e, 3o; NbCl5 1,944 atoms, NaNbO3 1,080,
  NaCl 216. Both sides also run the 0e segment's plain product.
- Timing: CUDA graphs of 20 calls, L2 flushed before each call (subtracted), 15 alternating blocks, medians. The
  fused kernel's tile is the fastest of four on a quick pass (32 atoms × 64 columns × 32 K for all three cells).

## Results (ms per call of the subgraph, one interaction)

| Cell | chain | fused | fused / chain | saved |
| --- | ---: | ---: | ---: | ---: |
| NbCl5 | 2.248 | 1.938 | **0.862** | 0.310 |
| NaNbO3 | 1.240 | 0.974 | **0.786** | 0.265 |
| NaCl | 0.232 | 0.280 | 1.209 | −0.049 |

Spreads ≤ 3.6 % between blocks.

**Exactness:** not bitwise. Both `dgated` and `dgate` differ from the chain at 7–8e-7 relative (1.1e-6 on NaCl,
where the chain's products are cuBLAS), so the record would be rounding-class. The difference is the order of
float32 sums inside `tl.dot` for a different tile shape, and the order of the m-sum.

## Caveats

- Synthetic operands; the real step's compiled gate backward may fuse more ops into the same kernel (the
  activation derivatives of the gates and scalars), which would change the chain's cost. A step-level A/B is
  needed before any record.
- Only the RTX 4000 Ada so far; the RTX 5060 Ti (local queue) and an A100 are not measured.
- An earlier run of the probe crashed with an illegal address: the fused closure (owning its output buffers)
  was dropped after capture and the expandable-segments allocator unmapped the memory. Fixed in the probe
  (`ae6f5e45`); no effect on the numbers above.
