# 3-T06: the compiled MD tier

Plan task 3-T06 (plans/phase-3.md): MD on `torch.compile` (default mode) without CUDA graphs,
`mode="compiled"`, rules 4 and 9, and the fallback's mode dimension graph → compiled → eager →
reference. SPEC §8.2, §9.3 rules 4 and 9, §9.4 step 2.

## What the tier is

- `engine/compiled.py`: `CompiledEngine`, the `GraphEngine` with `capture=False` and exact edge
  counts. The compiled model sees the edge dimension as dynamic from the first call
  (`EngineConfig.dynamic_edges`, 2-T13), so a neighbour rebuild with a new edge count does not
  compile again. A model with inexact padding runs here (rule 4).
- Planner: `mode` defaults to `None`. Without a mode the planner picks the graph tier, or the
  compiled tier for inexact padding (rule 4) or host callbacks every fewer than
  `RULE_9_HOST_CALLBACKS = 10` steps (rule 9; not with `reproducible=True`, whose qualified tiers
  are graph and eager). An explicit `mode="graph"` is the user's: rule 9 does not move it, and
  rule 4 refuses it, naming `mode="compiled"`.
- Fallback: when eager passes the reduced gate, a graph plan tries compiled before eager.
- Report: a `why:` line "compiled tier: no CUDA graphs (...)" with the reason (rule 4, rule 9 or
  `mode='compiled'`).

### Compiled equals graph within float32 noise (`tests/gpu/test_compiled_gpu.py`)

NaCl 3x3x3 (216 atoms), NVT Langevin 300 K, 2 fs, 100 steps, the same seed. Compiled
(`check="gate"`), then graph twice in one fresh process. Deviations are the maximum over the 10
committed rows.

| Model, backend, precision | max \|Δx\| compiled–graph | graph–graph repeat | ΔE compiled–graph (meV/atom) | repeat | Gate | Compiles |
| --- | --- | --- | --- | --- | --- | --- |
| MH-1 `mh1-r2scan`, hybrid, float32 | 2.2e-7 Å | 3.0e-7 Å | 3.3e-5 | 4.4e-5 | passed | one across 12 rebuilds, 37 edge counts |
| MP-0 `mp0-medium`, plain cuEq, float32 | 2.8e-7 Å | 2.2e-7 Å | 2.2e-5 | 1.9e-5 | passed | one across 12 rebuilds, 40 edge counts |

The compiled tier's difference from graph is the size of graph's own run-to-run float32 noise.

against graph 4.2; MP-0 15.7 against 3.7.

### Rule 9: graph against compiled with frequent host callbacks (`tools/ab_host_callbacks.py`)

MH-1 `mh1-r2scan`, hybrid float32, NVT Langevin 300 K, 1 fs. Both simulations live in one process,
are warmed up 200 steps, then timed round-robin: 8 blocks per tier and interval, each block 100
steps as `run(steps=k)` plus a callback (`committed()`, a sync and a host copy). Medians in ms/step.

| Structure (atoms) | Callback every | Graph | Compiled | Compiled / graph |
| --- | --- | --- | --- | --- |
| NaCl 3x3x3 (216) | 1 step | 3.87 | 16.73 | 4.32 |
| | 5 steps | 3.15 | 14.87 | 4.72 |
| | 10 steps | 3.09 | 14.64 | 4.74 |
| NbCl5 3x3x3 (1944) | 1 step | 22.96 | 34.45 | 1.50 |
| | 5 steps | 21.54 | 28.83 | 1.34 |
| | 10 steps | 22.27 | 30.37 | 1.36 |

Block spreads (max − min over median) were 1–41 %. The other workers' processes were not stopped,
because the conductor asked for reservations without `--quiet`. The ratios are 34–370 % away from 1,
far beyond that noise.

**Finding for the owner: graph stays faster than compiled with frequent host callbacks.** A
callback every step costs the graph tier 25 % on NaCl (3.87 against 3.09 ms/step) and 3 % on
NbCl5, while the compiled tier, which launches every kernel from the host without graphs, is
1.3–4.7 times slower at every interval. Rule 9 as written ("host_callbacks_every small (< ~10
steps) → compiled mode") therefore makes such runs slower on this GPU. The code follows the rule
today (`RULE_9_HOST_CALLBACKS = 10`). A rule-9 amendment (keep the graph tier for host callbacks,
and choose compiled for them only where capture is not possible) is the owner's decision; until
then, `mode="graph"` overrides it.
