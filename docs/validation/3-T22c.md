# 3-T22c: the mass-weighted fixcm projection as the MD default

Plan task 3-T22c, 22 October 2026, owner decision 37 (SPEC §10.4, §18). Follows
[3-T22](3-T22-fixcm.md) and [3-T22b](3-T22b-fused-projection.md); the design is in
[design/fixcm-projection.md](../design/fixcm-projection.md). Branch `fastmace/3-T22c`, synced with main
at 397da85 (after 3-T06b).

## What changed

- **Planner.** Under NVT `fixcm`, `IntegratorConfig.fixcm_projection="auto"` resolves to `"mass_weighted"`
  for MD too, with the decision code `fixcm-projection-md`. MC keeps `fixcm-projection-mc`. NPT and `fixcm`
  off resolve to `"ase"` (`fixcm-projection-ase`), and an explicit value is kept. This applies to both
  planners: the minimal planner (`fm.Simulation`, `fm.md`, the CLI) and `FixedPlanner`, which
  ResearchModule's `--engine fastmace` uses.
- **Temperatures.** One helper forms every reported temperature: `fastmace.io.trajectory.kinetic_temperature`
  over `degrees_of_freedom(natoms, integrator)`. That is 3N − 3 under `"mass_weighted"`, and 3N under
  `"ase"`, NPT and `fixcm` off. The thermostat's target is unchanged.
- **Resume.** A run keeps its projection:
  - records without the field read as `"ase"`, in both `simulation.json` and the restart file's plan;
  - an `"auto"` record whose stored plan ran `"ase"` keeps `"ase"`.

## Where reported temperatures change

Under the default (NVT, `fixcm=True`, `"auto"`), every one of these now counts 3N − 3 degrees of freedom:

| Place | Before | Now |
| --- | --- | --- |
| `temperature_K` in the thermo rows (`temperature.csv` chunks), written by `Simulation`, `fm.md`, `fastmace run` and `fastmace md` | 2 E_kin / (3N k_B) | 2 E_kin / ((3N − 3) k_B) |
| `fastmace.ase.Langevin`'s log (ASE's `MDLogger`) | `Atoms.get_temperature`, 3N | the logged frame carries ASE's `FixCom`: 3N − 3 |
| `Simulation.degrees_of_freedom` (new) | — | 3N − 3 |

Unchanged:
- the report and `metadata.json`, which carry the plan's decision, not a temperature;
- the CLI's printed lines;
- the trajectory frames, which carry momenta, not a temperature;
- NPT runs;
- runs with `fixcm=False`;
- runs with an explicit `"ase"`.

At N = 216 the new count reads 0.46 % higher for the same kinetic energy. The stationary kinetic energy is
also lower by the factor (N − 1)/N, because the projection holds (3N − 3) kT rather than ASE's 3N kT. So a
run at the same target reports the same temperature as before, while each species now sits at the target.

**ResearchModule.** `--engine fastmace` plans through `FixedPlanner`, so its NVT runs switch to
`"mass_weighted"`. `run.json` records the decision with its code. `--engine gpu`, the frozen research
engine, keeps ASE's projection. A/Bs between the two engines therefore need `fixcm_projection="ase"` on the
FastMACE side.
