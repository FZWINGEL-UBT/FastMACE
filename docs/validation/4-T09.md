## What it is

- **Optimizer names** (`protocols/profiles.py`, the conductor's answers to the prestart):
  - `gpu-LBFGS` and `gpu-FIRE`: `fm.optimize` on the graph engine (4-T05, 4-T06);
  - `ase-LBFGS` and `ase-BFGS`: ASE's on `fm.calc`'s calculator;
  - bare `LBFGS` and `BFGS` keep meaning ASE's, so existing protocol files are unchanged;
  - records (`protocol.json`'s stages and relaxation, `quench/settings.json`, `quench.json`)
    hold the resolved name;
  - the default is `gpu-LBFGS` (decision 47, since 4-T08 passed). The shipped protocols and the
    `anneal` profile name it.
- **Relaxers** (`protocols/quench.py`): `ASERelaxer` (`relax` on an ASE calculator, now also with
  ASE's `FrechetCellFilter`) and `GPURelaxer`.
  - The first call of `GPURelaxer` builds one `Simulation(optimizer=)`.
  - Every later call moves that engine to the next structure with `update(cell=, positions=)`, a
    canonical point. There is no compile or capture per frame. Each frame starts from a fresh
    optimiser state and keeps its own cell (decision 40's NPT frames).
  - The per-step energies and max forces go to the log file, not into the summary.
- **Quench** (`quench_run`):
  - takes a relaxer, or an ASE calculator for the ASE optimizers, and a directory name
    (`quench`, or `quench-NAME`);
  - `settings.json` is written first, and an interrupted quench continues only with the same
    settings;
  - `quench.json` records `engines`, the number of engines built. It is 1 for one composition.
- **Protocol runner:** the relaxation and the quench run through relaxers with the run's
  precision, D3 record and `EngineConfig`.
- **CLI:**
  - `fastmace relax STRUCTURE --model … [--head --fmax --steps --optimizer --repeat --precision
    --dispersion --d3-functional --cell-filter frechet --pressure --output]` writes the structure,
    a `.json` summary and a `.log`, and exits 1 if the relaxation did not converge;
  - `fastmace quench RUN_DIR [--into NAME --optimizer --fmax --max-steps --min-K --bin-K
    --per-bin]` works on any run with a schedule, trajectory frames and a restart. The settings
    come from the protocol's `[quench]`, else from the `anneal` profile.
- **A 4-T05 gap found here:** `Simulation.update(cell=)` with D3 failed. `DispersedForceField.reset_cell`
  called a `D3Term.reset_cell` that did not exist, and `D3PairList.reset_cell` would have been
  handed a CUDA tensor.
  - Fix: `D3Term.reset_cell` passes the cell to the list as a host array. The canonical point
    already rebuilds the D3 list (`rebuild_all`).
  - Found by the first Modal smoke (run a below). It is outside the plan's files; the conductor
    accepted it on this branch.
