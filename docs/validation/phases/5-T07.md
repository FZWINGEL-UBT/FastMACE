storm and production profiles.

## Finding for main (not changed in 5-T07)

A script that calls `fm.load` by label (`loading.load_pristine("mh1-r2scan")`) before it builds a
`Simulation` can hit the expandable-segments refusal (`ProcessConstraintError`, the second attempt above).
The load touches CUDA before the planner configures the allocator, which happens only in `hardware()`. The
likely fix is for the load to call `configure_allocator` first. This is not verified on the GPU beyond the
failure above. The conductor gives it to a small follow-up task; 5-T07 leaves main's loading unchanged.

**Fixed (24 October 2026, conductor, branch `fastmace/5-T07c`):** `load_pristine` (`fm.load`) now calls
`configure_allocator` before `prepare_hybrid_if_possible` (a no-op if `PYTORCH_CUDA_ALLOC_CONF` is set).
CPU test `tests/cpu/test_load_allocator.py`. GPU smoke on the RTX 5060 Ti (`mace_cueq_latest`, untimed FIFO
reservation): `fm.load("mh1-r2scan")`, then a CUDA allocation; `check_allocator` returns
`expandable_segments:True`.
