# 4-T10: front ends for the phase 4 integrators and optimisers

Plan task 4-T10 (`plans/phase-4.md`), SPEC §7.5–§7.7, decisions 44 (FixAtoms) and 48 (the ASE optimisers).
Branch `fastmace/4-T10`.

## What changed

- **`fastmace.ase` MD classes:** `VelocityVerlet`, `Bussi`, `NoseHooverChainNVT`, `IsotropicMTKNPT`, `MTKNPT`,
  `NVTBerendsen`, `NPTBerendsen` and `Inhomogeneous_NPTBerendsen`, on 4-T01's argument lists (`md.py`;
  `LATER` removed). Each takes its ASE 3.27 class's arguments, units and defaults. `NPTBerendsen` keeps
  ASE's deprecated `pressure` (bar) and `compressibility` (1/bar) and its `taut`/`taup` defaults. `Bussi`
  refuses `rng` (pass `seed=`) and a start at rest, as ASE does.
- **Centre of mass (conductor's answer to the prestart):** a class whose ASE original has no `fixcm`
  (`VelocityVerlet`, `Bussi`, NHC, MTK) defaults to `dof="ase"`: no centre of mass removed, ASE's count.
  `dof="auto"` is FastMACE's convention. The Berendsen classes pass ASE's `fixcm` through, as `Langevin` does.
- **FixAtoms (decision 44, after 4-T04):** every class goes through `Simulation`, so rule 1 decides at the
  first `run`:
  - FixAtoms runs with `VelocityVerlet`, `Bussi`, `NVTBerendsen(fixcm=False)`, and `LBFGS` and `FIRE` at
    fixed cell;
  - it is refused with the reason for NHC, MTK and NPT Berendsen, and with a `FrechetCellFilter`.
  - The `fm.calc` path (`planner/fixed.py`), which still refuses FixAtoms, is not used.
- **`fastmace.ase.LBFGS` and `FIRE` (decision 48),** `fastmace/ase/optimize.py`, on `Simulation(optimizer=)`
  and `relax`:
  - `atoms` is an `Atoms` or `ase.filters.FrechetCellFilter`, read into `fm.optimize.FrechetCell`; other
    filters are refused;
  - refused with the reason: `restart`, `use_line_search=True`, `maxmove`, `position_reset_callback`;
  - ASE's `Log` and line format for `logfile`, and `trajectory=` frames every `loginterval` steps;
  - an observer that changes `atoms` raises.
- **`fm.md(ensemble="NVE")`:** velocity Verlet from the structure's momenta.
  - `temperature_K`, `schedule` and `mc` raise `ValueError`.
  - `max_temperature_K` is max(2 T_kin, 1 K) (`quick.nve_max_temperature_K`).
  - `integrator=` takes every `fm.integrators` record.
  - CLI: `fastmace md --ensemble NVE`; `fastmace run` takes every record type; the `fastmace init` template
    lists them.
- **Report:** the header names the scheme (for example `NPT MTK full`). A non-canonical scheme gets
  `<scheme>: non-canonical: equilibration only (§10.2)`. MTK and NPT Berendsen carry the NPT barostat's
  experimental line.
- **`tools/ab_frontends.py --integrator`:** the ASE class against `Simulation` and `fm.md`, with every side
  on the shim's own record, from the same Maxwell–Boltzmann momenta.
- **`Simulation.add_metadata_block`:** the shims' `"ase"` block is part of the `Simulation`'s own
  `metadata.json` write (below).

## GPU A/B: the same step time as `Simulation` (§7.7 acceptance)

Local PC (WSL2), NVIDIA GeForce RTX 5060 Ti, `mace_cueq_oeq` (torch 2.14.1+cu130), hybrid cuEq/OEq,
float32, MH-1 r²SCAN (`mh1-r2scan`, SHA-256 `a522eb7f…`), NaCl 3×3×3 (216 atoms), 0.5 fs, 300 K. Time
constants 100 fs (thermostats) and 1000 fs (barostats), pressure 0. All sides run in one process with
alternating blocks of 300 steps after 300 warm-up steps. The source is an ext4 export of the commit,
because a `/mnt/d` checkout distorts timing (1b-T21b). Through `tools/ci/local_gpu.py run`, 23 October 2026.
The research-engine baseline is not involved: every side is FastMACE.

**Run 1** (e69db94, 3 blocks, order `simulation md ase`). Every class gives the same plan and the same gate
on all three sides:

| Class | `Simulation` ms/step | `fm.md` / `Simulation` | ASE class / `Simulation` |
| --- | --- | --- | --- |
| VelocityVerlet | 2.917 | 0.995 | 1.010 |
| Bussi | 2.977 | 1.003 | 1.012 |
| NoseHooverChainNVT | 3.000 | 0.996 | 1.017 |
| IsotropicMTKNPT | 3.684 | 1.000 | 1.018 |
| MTKNPT | 3.803 | 1.002 | 1.062 |
| NVTBerendsen | 3.000 | 1.003 | 1.020 |
| NPTBerendsen | 3.644 | 0.994 | 1.012 |
| Inhomogeneous_NPTBerendsen | 3.678 | 1.000 | 1.014 |

The ASE side was always slower. In MTKNPT every side's step time rose through the run (`Simulation`
3.79 → 4.01 ms), and the ASE side ran last in each round.

**Run 2** (e69db94, 12 blocks, the ASE side first), with the 1b `Langevin` class as the reference:

| Class | ASE class / `Simulation` | Extra per 300-step `run()` |
| --- | --- | --- |
| Langevin (1b) | 1.036 | 32 ms |
| VelocityVerlet | 1.024 | 21 ms |
| MTKNPT | 1.021 | 24 ms |

The gap was older than phase 4: the 1b class has it too. MTKNPT's 6 % in run 1 was the block order.

**Cause.** A CPU profile of `_finish_run` showed that after every `run()` the shim rewrote `metadata.json`
to add its `"ase"` block. `provenance.write_metadata` has been durable since 2-T10: it fsyncs the file and
its directory. So each call paid for two durable writes, about 12 ms on ext4 and more on `/mnt/d`, where
these runs wrote their output. 1b-T21b had measured no extra cost per call before 2-T10.

**Fix** (c10b4c0, kept by the conductor). `Simulation.add_metadata_block(name, provider)` merges
`{name: provider()}` into every record the `Simulation` writes, and the shims register their block there.
The `Simulation` writes before the frames queued behind it, so the block reports the run's own step and
last frame (one every `loginterval` steps from step 0). `close()` writes the final record after the drain.

**Run 3** (c10b4c0, as run 2):

| Class | ASE class ms/step | `Simulation` ms/step | ASE class / `Simulation` |
| --- | --- | --- | --- |
| Langevin (1b) | 3.033 | 3.018 | 1.005 |
| VelocityVerlet | 2.953 | 2.939 | 1.005 |
| MTKNPT | 3.948 | 3.961 | 0.997 (`fm.md` 1.011) |

The shims now cost what `Simulation.run` costs: the gaps are 0.5 % or less, against the 3 % noise floor
between processes. Every pair had the same plan and gate.

Raw data, one `metadata.json` and one log per run:
- `results/4-T10-rtx5060ti-20261024/` (run 1);
- `results/4-T10-rtx5060ti-20261024-followup/` (run 2);
- `results/4-T10-rtx5060ti-20261024-fixed/` (run 3).

The launchers are in the session notes (`4-T10-ab.sh`, `4-T10-ab-followup.sh`). The tool run is
`tools/ab_frontends.py --integrator NAME [--sides ...] --warmup 300 --block 300 --blocks N`.

The optimisers were not timed. Without observers or `trajectory=`, `run(fmax, steps)` is one
`Simulation.relax` call.
