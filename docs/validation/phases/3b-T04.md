## `tests/gpu/test_d3_integration_gpu.py`

| Check | Result |
| --- | --- |
| MACE + D3 against a D3-free engine + torch-dftd (float64), NPT, first step | energy 1.3e-9 eV/atom, force 2.1e-7 eV/Å, stress 7.4e-10 eV/Å³ |
| Checked, captured, 60 steps: committed forces against an eager call | 2.2e-7 eV/Å; 41 D3 builds, 1 regrowth, no graph dropped |
| Pipelined, captured, 14 early rebuilds beside the force call | 3.0e-7 eV/Å; 50 D3 builds, no graph dropped |
| Uncaptured, pipelined | 1.8e-7 eV/Å; 50 D3 builds |
| D3 on the engine's list against a D3 term built fresh at the end positions | bitwise equal (all three modes) |
| Fused integrator stage | on, with the D3 flag OR-ed in |
| Float64 MC copy: MACE float64 + D3 float64 kernel | 1.7e-14 eV |
| Rejected displacement block, 7 trial rebuilds | D3 list and kernel buffers bitwise unchanged |

The first version of this test found a race. An early pipelined rebuild beside the force call
(OPT2-T04) rebuilt the D3 list in place while the force graph read it. The D3 build now waits for
the reader stream (`DispersedForceField.rebuild`). The test then also showed that captured and
uncaptured MACE engines are not bitwise equal across checked and pipelined modes, because edge
buckets differ, as the existing MACE GPU tests already allow. It therefore checks each engine
against an eager call and a fresh D3 term instead.
