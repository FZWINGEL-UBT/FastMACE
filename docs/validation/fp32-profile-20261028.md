# Fine-grained profile of the default float32 MD path (28 October 2026)

Owner request, 28 October 2026: time FastMACE's default float32 MD path, the step and the setup, in as much detail as
possible, to guide the next optimisation round. Measurement only; no default was changed. Branch
`fastmace/fp32-profile-20261028`. The index of every earlier attempt is [the optimisation ledger](../optimisation-ledger.md);
each opportunity below was checked against it.

## Summary

- **Step (RTX 5060 Ti, 1 fs, 1000 K):** 2.72 ms (NaCl), 14.36 ms (NaNbO3) and 18.68 ms (NbCl5) per step in the engine
  loop. The force graph (stage B) is 96–99 % of the step. The integrator stage, the noise upload and the neighbour-list
  rebuild (0.03–0.13 ms of kernels per step, on a side stream) are each under 2 %.
- **Large cells are throughput-bound.** On NaNbO3 and NbCl5 some stream is busy 98 % of the step. The graph's two
  branches overlap by 2.9 ms (NaNbO3) and 1.9 ms (NbCl5). Gaps are 1 % of the step. **NaCl is launch-bound and
  under-filled:** the GPU is busy 86 % of the step under Nsight Systems (91 % by the replay profile), and the
  atom-level cuBLAS GEMMs are 54 % of its kernel time at 10–11 TFLOPS.
- **Largest kernel groups:**
  - **NbCl5:** the Triton `segment_gemm` products (26 % of kernel time), the cuBLAS GEMMs (20 %), the chunked
    convolution backward (12 %), the folded-layer input gradient (12 %, mostly beside the backward), the atom-level
    elementwise kernels (12 %) and `fused_folded_forward` (7 %).
  - **NaNbO3:** the input gradient (19 %), the convolution backward (18 %), cuBLAS (18 %), `segment_gemm` (14 %) and
    `fused_folded_forward` (11 %).
- **The engine loop is not the whole story:** through `fm.md` (Simulation with default output), the steady step is
  3.12 / 14.79 / 19.32 ms, that is +0.40 ms (+15 %) on NaCl and +3 % on the large cells. This overhead is new in this
  profile and is the largest opportunity found (O1).
- **Setup:** a warm `fm.md` start takes 34–41 s to the first step and a cold one 71 s (NaCl). The largest warm stages:
  - the first compiled call, 11.5–12.0 s (Dynamo traces twice: 2.4 s are a restarted first attempt);
  - two checkpoint conversions, 7.3–8.6 s;
  - the radial-table fit and certificate, 4.4–10.3 s;
  - 21 rewrite self-checks, 4.3–4.6 s;
  - rewrite resolution and planning, 2.7–3.8 s.

  Cold adds the OEq extension build (17.7 s) and doubles the first compiled call (24.4 s).

Tools (this branch):

- `tools/step_breakdown.py`: 2-T20a's tool, with `--timestep-fs` and a new `--pass nsys-steps`. It runs:
  - the main pass: wall time over 1,000 steps; CUDA events per stage; 10 eager force calls of the compiled model under
    torch.profiler, by kernel, operator and category; 10 force-graph replays (kernels, gaps);
  - an Nsight Compute pass: one eager force call, DRAM and L2 bytes, FLOPs and occupancy per kernel;
  - an Nsight Systems pass over 10 force-graph replays, every graph node traced;
  - `nsys-steps`: Nsight Systems over 300 whole MD steps, with NVTX ranges around each step, stage, rebuild and noise
    upload.
- `tools/bench/fp32_parts.py`: the same plan on the eager tier, which has the same enabled options (checked:
  identical sets). Every model module is wrapped in forward and backward profiler ranges, so kernel time is
  attributed per module, forward and backward separately.
- `tools/bench/fp32_setup.py`: `fm.md` with nested timers around about 50 setup functions, CUDA-synchronised outside
  captures. It also records torch.compile's phase times, the first step, and the steady state with output over
  1,000 further steps. It ran once cold (fresh cache directories) and twice warm per structure, plus once under
  cProfile.
- `tools/bench/fp32_streams.py`: stream concurrency and GPU idle holes from the `nsys-steps` database.
- `tools/bench/fp32_report.py`: the tables of this report.
- Launchers: `results/fp32-profile-20261028/run.sh` (local) and `tools/modal/fp32_profile.sh` (Modal, not run, see
  "Not measured").

Raw data: `results/fp32-profile-20261028/local/` holds every CSV and JSON, `tables.md` (all generated tables),
`streams.txt` and `setup_summary.txt`. The Nsight reports and profiler traces (385 MB) stay in WSL

## 1. The step

### 1.1 Stages (ms per step)

| Stage | NaCl | NaNbO3 | NbCl5 |
| --- | ---: | ---: | ---: |
| **Wall time, engine loop, uninstrumented** | **2.716** | **14.358** | **18.675** |
| B: forces + second half kick (CUDA events) | 2.612 | 14.162 | 19.080 |
| ACP: half kick, positions, neighbour check, compaction | 0.050 | 0.052 | 0.046 |
| Noise upload | 0.018 | 0.028 | 0.052 |
| C: compaction after a rebuild | – | 0.000 | 0.056 |
| Neighbour-list rebuild, event span (overlaps B on its own stream) | 0.358 | 1.228 | 1.244 |
| Neighbour-list rebuild, kernel time (Nsight Systems) | 0.034 | 0.130 | 0.119 |
| GPU idle between stages (events, rebuild overlap removed) | 0.08 | 0.05 | 0.05 |
| Rebuilds per 1,000 steps | 161 | 214 | 160 |
| Padded edges | 8,192 | 82,688 | 58,880 |
| Kernels per B replay | 233 | 317 | 275 |
| B replay: kernel time / span (profiler) | 2.471 / 2.616 | 16.681 / 13.991 | 20.813 / 18.793 |
| **Steady step through `fm.md` with default output** | **3.12** | **14.79** | **19.32** |

- **At 1 fs the list is rebuilt about every 5–7 steps** (2-T20a at 0.5 fs: about every 12). A rebuild's span is
  2.8–7.6 ms, but its kernels take 0.2–0.7 ms. The rest is waiting while B runs beside it (`overlap_rebuild`). Its
  cost to the step is the SM time it takes from B, at most the 0.03–0.13 ms of kernels per step. F5 (incremental
  neighbour list) stays below 1 %, as the ideas file estimated.
- **The B replay's kernel time exceeds its span on the large cells** because the graph runs two branches at once
  (1.2).
- **Engine against `fm.md`:** the engine loop agrees with opt8-T02's A/B times (NaCl 2.65–2.71, NbCl5 18.62–18.67 ms at
  300 K). The `fm.md` row comes from a different process and run, but the difference is far above the 0.4–1.1 % noise
  floor (O1).

### 1.2 Streams and idle time (Nsight Systems, 300 whole steps)

| Per step (ms) | NaCl | NaNbO3 | NbCl5 |
| --- | ---: | ---: | ---: |
| Step span under Nsight Systems | 2.901 | 14.410 | 18.612 |
| Some stream busy | 2.502 (86 %) | 14.072 (98 %) | 18.284 (98 %) |
| Main graph stream busy | 2.247 | 10.944 | 13.863 |
| Second graph stream busy | (0.200, alternate replays) | 5.975 | 6.202 |
| Overlap of the two | 0 | 2.915 | 1.856 |
| Idle holes ≥ 10 µs | 0.237 | 0.219 | 0.224 |

- **Second stream:** the convolution backward (`oeq_projected_backward`), part of the GEMMs and the symmetric
  contraction's backward run there. The folded-layer input gradient (`kernel`), `fused_folded_forward` and the rest
  run on the main stream.
- **The idle holes are three per step:**
  - after the B graph (`scatter_kernel` → `unrolled_elementwise_kernel`, 81–111 µs);
  - before the noise kernel (70–87 µs, large cells);
  - inside B (47 µs, large cells): after the chunked convolution backward's last chunk, the join of the two streams
    starts the next memset and GEMMs 25–48 µs late.

  Nsight Systems inflates the host part: without it, the events give 0.05–0.08 ms of idle time per step.
- **Inside the force graph** the replay profile has 0.14 ms of gaps on NaCl (232 boundaries, mostly under 5 µs) and
  0.15 ms on the large cells, including the join stall: 5.4 % and about 1 % of the replay.

The kernel sum exceeds the step on the large cells (two streams). A part's share is therefore of the work, not of the
critical path. step_breakdown's own categories predate `fused_folded_forward`, `segment_gemm` and the chunked backward,
so this table re-sorts its `ops.csv` by kernel name (`fp32_report.py`, `REFINED`). The old categories are in
`tables.md`.

| Module | NaCl | NaNbO3 | NbCl5 |

| Interaction 1 (`interactions.1`), backward | 1.089 (33 %) | 11.131 (52 %) | 14.697 (49 %) |
| Interaction 1, forward | 0.699 (21 %) | 4.119 (19 %) | 5.131 (17 %) |

| Interaction 0, forward | 0.419 (13 %) | 1.791 (8 %) | 2.924 (10 %) |

| Spherical harmonics, fwd + bwd | 0.093 (3 %) | 0.210 (1 %) | 0.159 (1 %) |
| Pair repulsion, fwd + bwd | 0.157 (5 %) | 0.187 (1 %) | 0.168 (1 %) |
| Readouts, scale/shift, atomic energies | 0.081 (2 %) | 0.141 (1 %) | 0.268 (1 %) |
| **Eager kernel time (without hooks)** | **3.282** | **21.191** | **30.269** |

Inside the interactions, the gated-rows linear blocks (`gated_rows`, MH-1's atom-level linears with their gates) are the
largest exclusive ranges. On NbCl5 they are 27 % (interaction 1, backward), 13 % (interaction 0, backward), 11 % and 8 %
(forward). Next come interaction 1's own range (convolution, radial last layer: 19 % backward, 5 % forward) and the
first-interaction reassociation (4 %). Kernels outside every range: 0.03–0.04 ms. The eager tier runs uncompiled, so
elementwise work and the pair repulsion take more kernels and time than in the compiled graph (3.28 against 2.47 ms on
NaCl). Its module shares are a map of where the compiled kernels come from, not their compiled cost.

## 3. Opportunities, ranked

Estimated gains are ceilings from the measured shares, for this card. Each still needs the usual gate, a same-process
A/B and confirmation on sm_120, Ada and the A100, under the owner's generality rule.

| Rank | Opportunity | Evidence | Estimated gain | Ledger check |
| ---: | --- | --- | --- | --- |
| O1 | **The `fm.md`/Simulation loop costs 0.40 ms per step on NaCl** (+15 %), +0.43 (+3.0 %) on NaNbO3 and +0.64 (+3.4 %) on NbCl5 over the engine loop. cProfile puts 0.35 ms per step of host time in `Simulation._advance` outside `engine.step`. The default output samples every 20 steps. First split it with an A/B: engine against Simulation without output against default output. Then keep the pipeline full across samples (event-guarded asynchronous copies, no host synchronisation on sample steps). | §1.1; `setup-*/setup.json` `steady_ms_per_step_with_output`; `setup-NaCl-cprofile/cprofile.txt` | up to 13 % (NaCl), 3 % (large cells) | New: no Simulation-against-engine step comparison is recorded. `async_output` makes the writes asynchronous; whether the sample steps synchronise is not recorded. |

Not proposed, because the ledger closes them, and this profile does not change their ceilings:

- the symmetric contraction (4–6 %, OPT3-T02: kernels at 72–96 % of memory speed of light);
- the folded-layer input gradient (beside the convolution backward; F0's ceiling 0.5 / 2.6 %);
- small-M GEMMs on NaCl (split-K, per-l branches and `tf32x3` rejected; `grouped_launch` 0.977 on sm_120 only, opt-in);
- the convolution's `w`/`dw` traffic (the session that owns the fused table → `w` → convolution kernel);
- the neighbour-list rebuild (0.03–0.13 ms of kernels per step on a side stream; F5 < 1 %);
- 16-bit stages (OPT4-T08).

## 4. Not measured

- **A100, L4 (Modal):** the L4 job (`tools/modal/fp32_profile.sh`, commit `312942df`) waited 2 h for L4 capacity
  ("waiting to be scheduled on a GPU_L4 worker") and was stopped without running. Metered cost $0.00; ledger row with
  exit "error". From 1 November the same script can run under the new month's budget, on the L4 or the A100
  (`--gpu A100`).
- **RTX 4000 Ada / A4000 (workstations):** all three permitted workstation GPUs were in use by other runs (leto, murphy:
  NaMOCl4; trillian: Energy_Hull); leeloo and coraline were busy with other users' jobs.
- **Nsight Compute on the chunked backward:** the per-chunk kernels of the convolution backward and the input gradient
  vary in number between processes. The ncu join cannot align them by launch order (the "?" row: 17 % of ncu time on
  the large cells), so their ncu bandwidths above are group averages.
- **Compiled kernel → module mapping:** Inductor's fused kernels carry no module names. The module attribution uses the
  eager tier (§1.5), and the compiled table (§1.3) uses kernel and operator names.
- **The cause of O1:** measured, not attributed. The cProfile run gives the host time outside `engine.step`, not which
  call in `_advance` holds the GPU idle.
- **The smoke run's setup step:** skipped because the desktop held the GPU at 21 % for 2 minutes (20:03 CET). The full
  run's idle checks then waited up to 30 minutes, and the desktop was idle throughout the full run.

## Reproducing

```bash
python3 tools/ci/local_gpu.py run --quiet --purpose "fp32 profile" -- bash results/fp32-profile-20261028/run.sh full ~/fastmace-runs/fp32-profile-20261028/local
python3 tools/bench/fp32_report.py ~/fastmace-runs/fp32-profile-20261028/local --label "RTX 5060 Ti, local" > tables.md
python3 tools/bench/fp32_streams.py ~/fastmace-runs/fp32-profile-20261028/local/{NaCl,NaNbO3,NbCl5}
```

`run.sh smoke ROOT` checks every pass on NaCl in about 15 minutes. The full run takes 60 minutes: Nsight Compute takes
9–20 minutes per structure.
