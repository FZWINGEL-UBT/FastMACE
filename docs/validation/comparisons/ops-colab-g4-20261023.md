# Colab driver validation on a G4 (ops-colab, 23 October 2026)

`tools/colab/fastmace_colab.py`, end to end on Colab G4 VMs. Records: `results/ops-colab-g4-20261023/`
(`colab.json`, `probe.json`, `setup.json`, and for the compat runs `compat.json` and `junit.xml`); ledger rows in
`results/colab-ledger.csv`.

- **Machine:** Google Colab G4, "Colab G4": NVIDIA RTX PRO 6000 Blackwell Server Edition, sm_120, 96 GB,
  driver 580.82.07, CUDA 13.0; 48 CPUs, 176 GB RAM.
- **Environment:** uv-managed Python 3.10.22, `tools/modal/requirements-hybrid.txt` with certifi 2026.10.19
  (torch 2.14.1+cu130, Triton 3.8.0, cuEquivariance 0.12.0, OpenEquivariance 0.7.0, MACE 0.3.16, e3nn 0.4.4,
  ASE 3.27.0, NumPy 2.2.6). The warm run also has `dftd3==1.6.0` (`EXTRAS`, added after the cold run).
- **Backend and precision:** whatever each test of the tier sets; the hybrid paths ran with OEq.
- **FastMACE:** the environment build on `135accd`, the compat runs on main `018db4f`. Driver: `fastmace/ops-colab`
  (the warm run on `1cfce13`). No research-engine baseline is involved.
- **Command:** `python tools/acceptance/compat.py --provider colab --label "Colab G4" --output $OUT`
  (`pytest tests/gpu -m compat`).

**Setup:** a VM is ready to run commands in about a minute without caches (allocation 5 s, payload upload
8 s once the source is gzipped, install 23–27 s). The goal of about a minute is met.

**The compile caches:** they help less than hoped on this tier.
- **Time saved:** over the 359 tests both runs share, 2448 s cold against 2198 s warm (−10 %). Tests that
  compile from scratch drop the most, for example `test_combo_kernels_change_no_value` from 86.7 to 23.6 s and
  `test_tiny_registry_plain_cueq_float64` from 75.7 to 25.0 s. The longest tests (the accuracy gates,
  reproducible mode, eager against graph, the MD smoke) are runtime, not compilation, and take as long warm.
- **Upload cost:** uploading the 513 MB cache from the PC (about 3.5 MB/s) costs 154 s of the saved 250 s,
  so the net gain per run is about 100 s.
- **Delta:** the warm run added an 18 MB part (`001.tar.gz`).
- **Larger gains:** caches pay off more for jobs that compile much and run little, and on a faster uplink.

**Findings for 4-T13:**
- **Combo kernels:** `test_combo_kernels_change_no_value` failed cold on sm_120: 1.19e-6 against
  2 × 4.77e-7. It passed warm, so it sits at its tolerance.
- **dftd3:** the 16 simple-dftd3 cross-check tests skip without `dftd3`. With it (warm run) they pass.

**Driver problems found and fixed on the way:**
- **New-VM upload errors:** the VM's file API answered HTTP 500 just after `colab new`, so transfers are
  retried.
- **Upload size limit:** `colab upload` sends one base64 JSON request; 64 MiB went up and 80 MiB failed with
  HTTP 400. The driver uploads 48 MiB chunks, which the VM joins.
- **Hung polls:** a `colab exec` poll can hang past its timeout (this lost the first warm run's records), so
  polls reattach.
- **Name collisions:** two jobs started in the same second shared a name (4-T13), so default names carry a
  random suffix and live names are refused.
- **Driver library:** Colab's `/usr/lib64-nvidia/libcuda.so.1` is now an OEq driver candidate (A100 pilot).
