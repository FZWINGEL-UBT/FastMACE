## Item 1: species-change events against fixed species

### Method (`tools/bench/event_speed.py`)

- **Setup:** two `Simulation` sides in one process. MH-1 `matpes_r2scan`, hybrid float32, Langevin NVT,
  1 fs, friction 0.02/fs, 1500 K target, the same seed on both sides. NaCl and NbCl5 3×3×3.
  - **fixed:** `Workload(max_temperature_K=1500)`.
  - **events:** `Workload(max_temperature_K=1500, species_changes=True)`.
- **The event (host path):** after every 100 steps, `Simulation.update(species=…, momenta=…)` swaps the
  species of one atom of each species, with `exchange` momenta (the two atoms swap velocities with their
  species, §10.4), and does no energy evaluation. Its cost includes the force recompute and the canonical
  rebuild (conductor answer 2).
  - The pairs come from a seeded stream, the same in every run.
  - The species read and the momenta read use `Simulation.committed()`.
- **Timing:** each side advances with `run(100)`, so one timed unit is 100 steps plus, on the events side, one
  event.
  - 300 warm-up steps (3 events), then 12 blocks of 300 steps (3 events each), alternating through
    `fastmace.bench.ab.run_ab`.
  - Both orders: build order fixed-first with pattern ABAB, and events-first with ABBA.
- **Result:** the rate ratio median(fixed) / median(events). The run passes at ≥ 0.90.
- **Validity:** a run is invalid if anything compiled, any graph was captured
  (`engine.info()["recapture_log"]`) or another process used the GPU while timing.
- **Settling:** at 1500 K, new edge sizes keep appearing after 300 steps (the breakdown below saw 3 on NaCl).
  So after the 300 warm-up steps, the series keeps warming up untimed (`--settle 5`) until 5 chunks in a row
  add no graph capture on either side, for at most 3000 more steps. The record holds the settle steps.
- **Recorded per side:** skin, capacity headroom, edge-bucket fraction, edge bucket and capacity, and
  re-capture budget. Rule 11 (3-T05, merged) sizes these for the events side, which declares species changes;
  the fixed side keeps phase 1a's values. Also recorded: captures, neighbour rebuilds, canonical points, final
  temperature and potential energy, and species counts.
- **Rows:** the structure's species, and the superset {Na, Nb, O, Cl} on both sides (conductor answer 3).
- **Two designs:**
  - **random swap:** each event swaps a new random pair, always accepted;
  - **swap-back** (`--swap-back`, 781c376): every second event swaps the previous pair back.

### Random swaps drift the configuration (why swap-back is the measurement)

- **The random-swap design adds disorder at every event.** Its swaps are always accepted (no Metropolis), so
  each event adds antisite disorder, and the events side drifts away from the fixed side:
  - **energy:** it ends 0.25–0.29 eV/atom higher on NaCl (−6.41 to −6.44 against −6.69 to −6.70) and
    0.15 eV/atom higher on NbCl5 (−10.265 against −10.418);
  - **edge counts:** on NaCl it reaches a padded edge size the fixed side never reaches (9216 against at most
    8704).
- **That costs a capture in the timed window on NaCl.** Its edge count keeps climbing into new buckets, so the
  first visit to a new bucket can fall in the timed window, however long the settle.
  - Every random-swap NaCl run but one has exactly one capture, always on the events side: local NaCl-ba, all
    four leeloo NaCl runs and both L4 NaCl runs.
  - The NbCl5 runs have none: its edge count stays in the 58,880 bucket.
- **It is one new `('B', size)` variant, not a dropped graph.** An invalidation would recapture several keys.
  The capture comes from the drifting configuration, not from the event path. **There is no finding for 3-T03
  or 3-T04:** an event in steady state does not cost a capture.
- **Swap-back is therefore item 1's measurement.** It still calls `Simulation.update` on two atoms every 100
  steps (conductor answer 1), while the system stays statistically like the fixed side. The random-swap rows
  below are labelled "drifting configuration" and are not the measure.
- **The record now holds the evidence.** From 781c376, each capture and invalidation while timed (step, key,
  reason) is recorded, with each side's edge count before every block.

**Where the time goes:**

- If a canonical point replayed the captured force graph of the current edge size (one step's force part,
  about 3 ms on NaCl), a NaCl event would cost about 7 ms. The expected ratio would then be about 0.98.

## Item 2: MC attempt cost

**Method:** `tools/bench/mc_cost.py`, MH-1 hybrid float32, 1500 K.
- **One process per row group.** MD steps, energy-only evaluations and the captured attempts alternate in
  timed blocks, rotating and mirrored.
- **Swaps:** blocks of 100 (NaCl) or 50 (NbCl5). While timing, decisions are forced to reject, so the same
  kernels run and the state stays.
- **Displacements:** the plan is made for a displacement workload (`max_displacement_A=0.1`), so rule 11 sizes
  the skin for it and the MD row runs at that skin. Two attempt paths:
  - "no trial rebuild": δ = 0.1 Å, captured;
  - "trial rebuild": δ equal to the skin, so every attempt takes the host path.
- Each value is the median of the per-round ratios to one MD step of the same process.
